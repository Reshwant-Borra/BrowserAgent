# BrowserAgent V2

One small loop over the browser you already have open.

```
your goal
   -> observe the current page
   -> retrieve a few relevant memories
   -> build a small, bounded prompt
   -> Qwen3 8B picks ONE action
   -> validate it
   -> (ask you / hand over to you, if needed)
   -> execute
   -> re-observe and verify deterministically
   -> update compact state
   -> repeat
```

No planner agent, no critic agent, no router. The plan is a list inside the task state. Eight
modules under `agent_v2/`, and nothing in them branches on the identity of a website.

Around that loop are four deterministic boundaries. They are not more agents — they are
bookkeeping BrowserAgent does for itself, because these are the things a model must not be
trusted to decide about itself:

| the model decides | BrowserAgent decides, deterministically |
|---|---|
| what to do next | whether the action actually worked |
| what is worth writing down | whether a page really showed it |
| what to claim in the answer | whether the claim has provenance |
| which numbers matter | what the arithmetic comes to |
| what might be worth remembering | whether it may outlive the task |

## Getting started

### 1. Start the model

```bash
ollama serve
ollama pull qwen3:8b
```

### 2. Start a persistent Chrome, once

Everything runs in *this* browser, so log into whatever you normally use and leave it open.

```bash
# Windows
chrome.exe --remote-debugging-port=9222 --user-data-dir="%CD%\runtime\browseragent_persistent_profile"

# macOS / Linux
google-chrome --remote-debugging-port=9222 --user-data-dir=./runtime/browseragent_persistent_profile
```

Or let BrowserAgent find Chrome and start it for you:

```bash
python -c "from pathlib import Path; from cli.launcher import ensure_chrome_cdp; \
print(ensure_chrome_cdp('http://127.0.0.1:9222', Path('./runtime/browseragent_persistent_profile'))[0].detail)"
```

Log in to your sites in that window. Sessions persist in the profile, so you do this once,
not once per task.

### 3. Give it a task

```bash
python -m agent_v2 "Find the current stable Node.js version on nodejs.org"
python -m agent_v2 "Compare the pricing pages of these two products and tell me which is cheaper"
python -m agent_v2 --start-url https://example.com "What is this page for?"
```

BrowserAgent attaches over CDP, works in that browser, and on exit **disconnects only**. Your
Chrome keeps running, your profile is untouched, and every tab you had open is still there.
Tabs the agent opened itself are the only ones it will ever close.

## When it needs you

Passwords, 2FA, passkeys and CAPTCHAs are yours. The agent cannot type into a password field
— that is refused in `agent_v2/actions.py`, not merely discouraged in the prompt — and the
observer never reports a password field's value, so the model never sees one.

```
========================================================================
HANDING OVER TO YOU
  This page needs a password. Please sign in yourself in the browser, then resume.
  page: https://example.com/login
  Do it in the browser window, then come back here.
  (BrowserAgent never sees or stores what you type.)
========================================================================
Press Enter when you're done (or Ctrl-C to stop):
```

Sign in in the Chrome window, press Enter, and it re-reads the page and carries on. In a
non-interactive shell it saves state and tells you how to resume:

```bash
python -m agent_v2 --resume v2-ab12cd34ef
```

Consequential actions — submitting, buying, deleting, sending — stop and ask first. Pass
`--yes` to approve them automatically.

## What it may claim

Qwen3 8B, asked for something it cannot find, will produce a plausible version number, an
authoritative-sounding source, or a price — fluently, and in the same voice it uses for
things it actually read. That is the most damaging failure a research agent has, because the
answer *looks* right. Instructions do not fix it; nor does asking for quotation marks, since
the model simply stops using them.

So BrowserAgent keeps its own record of what happened, and checks the answer against it.

**Visited resources.** A page exists in the record only because `observe()` returned it.
Finding a link does not count. Naming a URL does not count. A redirect files the requested
URL as an alias of the page that actually loaded, so citing either resolves to the same
place. Canonicalisation is conservative: `www.` and tracking parameters go, the path stays —
two pages on one host are two sources.

**The evidence ledger.** Every `add_facts` note the model writes is checked against the page
it was written against before it becomes evidence. Every figure in it must be a figure that
page showed; every quotation must be on it; every site it names must be one this task opened.
A note that fails is still kept — the model needs its own working notes — but it is marked
`(unverified)` and no evidence record exists for it, so it can never support the final answer.
Evidence ids are minted by BrowserAgent and carry a key derived from the task id, which is
what makes "that id belongs to a different task" a structural rejection rather than a
convention. **The model never authors an id.**

**The claim contract.** `finish` may carry a list of claims, each naming the evidence it
rests on:

```json
{"action": "finish",
 "answer": "Widget A is £159.00, Widget B is £89.00 — A costs £70 more.",
 "claims": [{"text": "Widget A is £159.00", "evidence_ids": ["ev_a91c_1"], "kind": "source"},
            {"text": "A costs £70 more",    "evidence_ids": ["ev_a91c_3"], "kind": "derived"}]}
```

Each id is resolved; unknown, foreign-task and invalidated ids are rejected. The figures in a
claim must appear in the evidence it cites, which is what catches a *real* price attached to
the wrong product.

**And the answer itself**, whether or not any claim was declared — because nothing obliges
the model to declare one. Every significant figure in the answer must be one the task can
account for, every quotation must be on a page it loaded, and every site it names must be one
it opened. Punctuation is irrelevant: `"The price is $99."`, `The price is $99.` and
`price = 99` are the same claim and are checked identically.

Four kinds of claim, because grounding must not make synthesis impossible:

| kind | example | what it needs |
|---|---|---|
| `source` | "Widget A costs £159.00" | evidence, and the figure must be in it |
| `derived` | "A costs £70 more than B" | a compute record, whose own inputs are evidence |
| `synthesis` | "B looks like better value for occasional use" | nothing — but its figures must still be accountable |
| `meta` | "I opened two of the three pages" | agreement with what the run actually did |

When something does not check out, the model is told exactly which part and asked to go and
look. If it stands by the answer, the answer is handed over **with the defect named**:

```
Widget A costs $159.00 and Widget C costs $42.50.

[NOT VERIFIED — figures not found on any page this task opened: 42.50]
```

That is the guarantee. Not that the model never invents anything — it does — but that an
invention is never presented as though it had been read off a page. Every run is classified
`FULL_SUCCESS`, `PARTIAL_GROUNDED`, `SAFE_FAILURE` or `UNSUPPORTED_SUCCESS`, and the last of
those is only reachable by shipping an unsupported claim *without* the disclosure. The
release gate requires it to be zero.

## Arithmetic

Asked whether 3.14 is larger than 24, an 8B model is a coin flip. Asked whether two prices
need subtracting, it is reliable. So it chooses the operation and BrowserAgent does it:

```json
{"action": "compute", "operation": "subtract",
 "operands": ["159.00", "89.00"], "labels": ["Widget A", "Widget B"],
 "evidence_ids": ["ev_a91c_1", "ev_a91c_2"]}
```

Fourteen operations — compare, min, max, sort, add, subtract, multiply, divide, percentages,
count, date and version comparison. The result becomes a derived evidence record with lineage
back to the pages the operands came from, so "A costs £70 more" is citable.

There is no expression language, no `eval`, no `exec`, no generated JavaScript or Python: the
model cannot express a computation `agent_v2/compute.py` does not already implement. Operands
are literals that get parsed, never evaluated, and anything ambiguous is refused rather than
guessed — `03/04/2020` is April in most of the world and March in the United States, so the
tool asks for `YYYY-MM-DD` instead of picking one.

A computation only *confers* grounding if its operands were themselves accountable. Otherwise
`add(42.50, 0)` would launder an invented price into an authoritative computed one.

## Memory

Stored in SQLite at `runtime/v2/memory.sqlite3`, entirely outside the model.

```bash
python -m agent_v2 --memories     # everything it has learned
python -m agent_v2 --no-memory "…" # run without it
```

At the end of a task it extracts at most four durable things — a user preference, how a site
behaves, an approach that worked, a lesson from a failure. On the next task it retrieves a
handful of *relevant* ones (FTS5 + bm25, scored by importance, domain match and recency); the
rest of the store never reaches the prompt. Contradictory memories supersede rather than
accumulate.

Asking the extractor for durable knowledge mostly works. What happens when it does not is a
deterministic filter on the way in — `classify_write` in `agent_v2/memory.py` — which refuses:

| refused | example the extractor actually produced |
|---|---|
| credentials | anything matching a password, code, token, key or card pattern |
| transient values | *"Python version 3.14.7 is the latest"*, *"Node.js stable version is v26.8.1"* |
| one-off counts and prices | *"The search returned 7 results for that query"* |
| listing positions | *"The best value candidate was the second row of the results table"* |
| the run narrating itself | *"I successfully retrieved the latest stable version of Python"* |
| capability boasts | *"I can compare version numbers between different software projects"* |
| goal restatements | *"The goal was to quote a specific sentence from example.com"* |

Every one of those is a row from a real dev or holdout run. `python -m evals.audit_memory`
reads a live database, classifies each row, and prints what today's policy would refuse —
which is what the patterns above are answerable to, rather than to intuition. On the database
those runs built, 23 of 159 rows would now be refused.

What survives is the reusable kind: *"Search results only load once you scroll to the
bottom"*, *"This shop shows prices only after you have chosen a delivery country"*, *"The user
prefers nonstop flights"*. Selective persistence, not zero persistence.

TaskState is not long-term memory. The evidence ledger is not long-term memory. Both are
per-task and neither is ever consulted by another task.

## Running the tests

```bash
python -m pytest tests/v2 -q                    # V2 unit + integration (real browser, faked model)
python -m pytest tests/unit tests/integration -q # legacy regression, unchanged by V2
```

| file | what it covers |
|---|---|
| `tests/v2/test_ledger.py` | resource identity, evidence identity, what may become evidence |
| `tests/v2/test_grounding_attacks.py` | the loop under attack — fabricated sources, planted evidence ids, prompt injection |
| `tests/v2/test_compute.py` | the arithmetic itself, including the cases a small model gets wrong |
| `tests/v2/test_memory_policy.py` | what may outlive a task, tested at the write boundary |
| `tests/v2/test_bounded_context.py` | a sixteen-page run whose prompt does not grow |
| `tests/v2/test_loop.py`, `test_actions.py`, `test_state.py`, `test_memory.py` | the loop itself |

The attack tests script the model to misbehave the way Qwen3 8B actually misbehaves. The bar
is never "the model behaves" — it is that none of it reaches the user as grounded.

## Real-web evaluation

Tasks are YAML data under `evals/suites/`; no agent code imports anything from there.

```bash
python -m evals.run_realweb --suite dev --trials 3            # development capability suite
python -m evals.run_realweb --suite holdout --trials 3        # held-out suite, run cold
python -m evals.run_realweb --suite grounding --trials 3      # the tasks the hardening exists for
python -m evals.run_realweb --suite dev --tasks table-extraction
python -m evals.audit_memory --verbose                        # what the agent made durable
```

`--trials` matters. One run of a stochastic model is an anecdote; the summary reports per-task
pass rate, spread and flakiness across trials rather than a single number.

Results, per-task metrics and full step traces land in `runtime/v2/evals/<suite>-<stamp>/`,
including each run's `evidence.json` — the ledger exactly as the run built it.

Validators are objective, and grounding is one of them: expected substrings and regexes, which
domains the agent actually loaded, how many sources it observed, how much evidence it
collected, whether it did the arithmetic rather than guessing it, and — standing over all of
them — whether the answer carries any claim the ledger cannot account for. An answer that
sounds right but was never read off a page fails.

Two demonstrations run against live sites:

```bash
python -m evals.demo_memory      # task 1 learns, task 2 retrieves only what is relevant
python -m evals.demo_takeover    # real login: pause, human signs in, resume, no leak
```

## Configuration

`config/default.yaml`, section `v2:`. The defaults are deliberate:

| key | default | why |
|---|---|---|
| `max_total_tokens` | 3900 | hard ceiling on the whole prompt, enforced per block |
| `page_tokens` | 1500 | the page is the only block allowed to absorb overflow |
| `memory_tokens` / `memory_top_k` | 380 / 6 | a handful of memories, never the store |
| `evidence_tokens` / `evidence_top_k` | 340 / 6 | a handful of evidence records, never the ledger |
| `keep_alive` | `30m` | one model call per action; reloading 8B weights between steps costs more than the step |
| `max_steps` | 40 | with a wrap-up warning as the budget runs low |

Which agent you get is decided by the entry point, not by a flag:

```bash
browser-agent "…"        # V1 — everything under agent/, unchanged
python -m agent_v2 "…"   # V2
```

`agent.version` exists in `config/default.yaml` and defaults to `v1`, but nothing currently
reads it — the two agents have separate entry points, so installing V2 changes no existing
behaviour whether or not that key is set. **Rolling back to V1 is running `browser-agent`.**
Nothing under `agent/` has been changed or removed by any of this, and the legacy regression
suite is still run in full on every change.

## Measured

Real public websites, Qwen3 8B over Ollama, three trials of every task on both sides. The
baseline is the previous commit run in a worktree on the same machine against the same sites,
so the comparison is matched rather than a remembered number. Raw per-run traces, including
each run's evidence ledger, are under `runtime/v2/evals/`.

### Held-out suite — 30 runs a side

| | baseline | hardened |
|---|---|---|
| runs passed | 24/30 | **25/30** |
| median model calls | 7 | 8.5 |
| median browser actions | 2.5 | 3 |
| median seconds | 13.5 | 15.5 |
| median peak prompt | 10,024 chars | 13,417 chars |
| outcomes | — | 25 FULL_SUCCESS, 2 SAFE_FAILURE, 3 stopped for a human |
| **UNSUPPORTED_SUCCESS** | — | **0** |

Three tasks got better, one got worse. `dynamic-repo` fell from 3/3 to 1/3: on a 12-step
budget, two grounding challenges were enough to run it out of steps, and it ended with a
grounded partial answer rather than a complete one.

### Development suite — 30 runs a side

| | baseline | hardened |
|---|---|---|
| runs passed | 26/30 | 23/30 |
| median model calls | 8 | 12 |
| median seconds | 11.8 | 28.8 |
| outcomes | — | 27 FULL_SUCCESS, 2 PARTIAL_GROUNDED, 1 SAFE_FAILURE |
| **UNSUPPORTED_SUCCESS** | — | **0** |

Three tasks each lost one trial in three. Grounding costs steps: a challenged answer means
going back to the page, and on this suite that is roughly half again as many model calls and
about twice the wall time. That is the trade, and it is stated rather than buried.

### Grounding suite — 15 runs

| | |
|---|---|
| runs passed | 14/15 |
| tasks green in every trial | 4/5 |
| outcomes | 15 FULL_SUCCESS |
| **UNSUPPORTED_SUCCESS** | **0** |
| median model calls / actions / seconds | 13 / 5 / 26.7 |
| median peak prompt | 13,267 chars |

The one failure is `multi-source-research` in one trial of three: the model opened
python.org, never went to the other two sites, and said so. A grounded incomplete answer,
which is what the failure policy prefers to an invented complete one.

An earlier pass of this same suite scored 11/15 with two runs labelled PARTIAL_GROUNDED. Both
were **false alarms** — an apostrophe in "It's Only the Himalayas" was being read as an
opening quotation mark, and "v26.8.1" on a page did not make 26 an accountable figure. Fixing
those two took the suite to 14/15 with nothing labelled. That is the shape of the risk this
mechanism carries: a check that cries wolf teaches the user to ignore the label.

### What the mechanism actually caught, on the live web

Not a fixture — this is a real trial of the three-source research task, from the trace:

```
step 4  finish   → "Python 3.14.7, Node.js 22.11.0, Go 1.22.0"
        rejected   no page you opened shows 22.11.0, 1.22.0
step 5  open_url   nodejs.org
step 6  finish   → still asserting both
        rejected   Node.js 26.8.1 states a figure its evidence does not show
step 7  click      through to the release page
step 8  finish   → "Python 3.14.7, Node.js 26.8.1, Go 1.22.0"
                   [NOT VERIFIED — figures not found on any page this task opened: 1.22.0;
                    sources this task never opened: golang.org]
```

Two invented version numbers became two real reads because the agent was told which part of
its own answer had no source. The third stayed invented — and was labelled rather than shipped
as fact. Before this work, all three shipped clean.

### Memory

After 75 real task runs the store holds 216 memories, **none** of which today's write policy
would refuse. The pre-hardening store built by the same suites held 159, of which 23 (14%)
would be refused — version numbers, prices, one-off counts and the run narrating itself.
`python -m evals.audit_memory --verbose` reproduces both figures.

### Credentials

`python -m evals.demo_takeover` drives a real login, hands over to a human who types the
password into the browser, resumes, and finishes. Every channel that could have carried the
secret is then searched for it — the prompts the model saw, the step log, the persisted task
state, the evidence ledger, spilled facts, and long-term memory. All six clean.

## What this does not do

Worth being plain about, because the guarantees above are narrower than they might read.

**Provenance is not truth.** If a page states something false, the evidence record faithfully
records the false thing along with the page it came from. What is guaranteed is that a claim
traces to something this task really read — not that what it read is correct.

**Containment is not entailment.** Whether a paraphrase is faithful to a page cannot be
decided deterministically, and this deliberately does not pretend otherwise. What is checked
is the part that can be: figures, quotations, named sites, and coined names. A sentence that
reworks a page's meaning while keeping its numbers will pass. Adding a second model to judge
entailment was considered and rejected — it would double the cost to produce an opinion no
more reliable than the first one.

**Small bare integers are not checked.** "36 months" and "$70" are; "3 pages" and "top 10"
are not, because flagging those would cry wolf on ordinary prose. The unit lexicon in
`agent_v2/ledger.py` is where that line is drawn.

**Ollama's grammar does not enforce `minItems`.** `plan_json_schema` asks for a non-empty
`pending` on the first turn and sometimes gets `[]` anyway, which quietly disables the
"you still have plan items outstanding" nudge for that run. The nudge is a prod, not a
correctness boundary, so it is left as it is rather than paid for with an extra model call
on every task.

**Grounding costs steps.** A challenged answer means going back to the page. On the
development suite that is about half again as many model calls and roughly twice the wall
time; on the held-out suite it is closer to 20%. One held-out task now runs out of its step
budget where it used to finish. Nothing here is free.

**Qwen3 8B remains Qwen3 8B.** It still picks inefficient routes, misreads pages, and gives
up on multi-source tasks it could have finished. None of that is what changed here. What
changed is that when it does, the result says so.

**Three false-positive fixes postdate the suite figures above.** The apostrophe, version-major
and sentence-initial-capital fixes landed after the development and held-out runs. Each
strictly removes spurious rejections — never adds one — so those two tables are a floor
rather than a current reading. The grounding suite was re-run across the first two and
improved; the third is covered by tests only, because the browser this machine was measuring
against had by then accumulated several hundred leftover tabs and would no longer stay up.
That leak is fixed (`BrowserSession.close_agent_tabs`, called by the evaluation harness
between tasks), but the numbers were not taken again afterwards.

## Where things are

| file | what it does |
|---|---|
| `agent_v2/agent.py` | the loop, the safety gates, the grounding checks |
| `agent_v2/actions.py` | what the model may say, and validation against the live page |
| `agent_v2/state.py` | compact working state; facts spill to disk rather than being dropped |
| `agent_v2/ledger.py` | which pages were really observed, and what evidence really exists |
| `agent_v2/grounding.py` | what may be presented as supported, and how a shortfall is disclosed |
| `agent_v2/compute.py` | the fixed set of deterministic operations |
| `agent_v2/memory.py` | durable cross-task memory, and what may become durable |
| `agent_v2/prompts.py` | the eight prompt blocks and their budgets |
| `agent_v2/browser_ops.py` | execute an action, own the tabs, verify the result |
| `evals/` | real-web harness, task suites, memory audit, demonstrations |

Reused unchanged from the existing codebase: `browser/playwright_backend.py` (the CDP-attach
lifecycle), `browser/observer.py`, `browser/state_hash.py`, `browser/tabs.py`,
`inference/llama_client.py`, `agent/token_budget.py`, `agent/loop_detector.py`, and
`agent/schemas.py`'s risk classifier.
